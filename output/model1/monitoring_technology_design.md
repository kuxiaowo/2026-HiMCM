# 无人机、卫星与人员协同的精简建模方案

日期：2026-10-05。状态：已核对题目第1、2页对技术、人员协同、战略部署与敏感性分析的要求，并核对NASA FIRMS的VIIRS活跃火产品说明。本文件确定技术如何接入现有模型；尚未取得本园无人机编制、实际飞行日志、告警记录或资源效能校准数据，也没有接入实时告警服务。

## 1. 第一版采用决定

保留现有分区保护价值与偷猎/火灾需求。把泛化的“监测投入”具体化为无人机飞行小时，地面人员使用保护人时分配；卫星作为全园共享的信息来源，其解译与核查仍占用人员。固定监测设备作为扩展，AI识别作用合并到识别效率与告警处理工时。题目列举的技术不要求逐一采用。

技术作用于发现、核查与响应环节，不直接增加区域生态价值，不自动降低既有历史火暴露，也不以设备数量直接换算为真实损失下降。

| 资源/技术 | 第一版作用 | 分配或计量方式 |
|---|---|---|
| 地面队伍 | 巡护预防、现场发现、告警核查和处置 | 地面保护人时；由可用人员和固定班次换算 |
| 无人机 | 重点区域巡查、疑似事件核查、火情观察 | 各区飞行小时，包含往返和现场飞行 |
| 卫星 | 全园生态背景、燃烧变化和火情告警 | 固定信息服务；预留解译与核查人时 |
| 固定摄像头/传感器 | 水点、通道等局部持续观测 | 本版暂不新增决策变量，后续按台数及覆盖区建模 |
| AI辅助识别 | 减少人工筛查或改变发现质量 | 并入统一监测效能、处理工时；保留误报漏报情景 |

卫星公开影像的取得不等于已建立告警服务。本园实际无人机数量若不可取得，可设不同机队规模的规划情景，不虚构现有装备编制。

## 2. 区域需求与资源效果分开

沿用道路进入便利度、历史晚旱季火暴露、降水年景以及与各类威胁对应的保护价值，形成分区需求。监测技术属于应对需求的资源，不再作为“高价值”或“高威胁”加分项。

两类威胁分别评价发现与响应：

- 偷猎侧：地面巡护与无人机巡查提供发现机会；卫星的公开活跃火产品不给偷猎检出贡献。道路进入便利度继续复用既定算法。
- 火灾侧：地面观察、无人机与卫星告警共同提供发现机会。火管理处置仍需具备相应能力的地面队伍；不能把所有巡护人员默认等同于消防人员。

第一版可设地面队伍按固定比例或班次承担相应任务，将专业能力差异合并到少量全园统一的响应效能情景。增加飞行小时的收益逐渐递减，已经反复覆盖的范围不会无限增加保护水平。地面巡护同时具有独立的发现、威慑作用，无无人机时仍可产生保护效能。

对每类威胁，技术新增的处置改善由“发现水平 × 及时有效响应水平”描述。两项在缺乏实测校准时是模型指标，不声称为实测概率；不得把该乘积再次乘到已经包含相同发现/响应作用的既有改善项上。

总响应时间拆为：

`发现等待 + 核查与调度 + 地面到达时间`。

其中地面到达时间继续使用已有道路图和驻点到区域的T_bi。无人机飞行时间使用空中距离和航速，不能直接复用道路最短通行时间。发现等待受巡查频率和卫星过境机会影响；固定作业小时数不足以推断所有班次均被覆盖，因此需明确固定巡查时段，并比较白天集中与分时巡查情景。

## 3. 直接决策变量与约束

第一版只保留两类直接投入：

- `x_i`：分配给区域的地面保护人时，计入出行、巡护、现场核查与响应占用。采用固定驻点与班次，按角色预留响应能力；同一人员同一时段不重复用于不同任务。
- `h_i`：分配给区域的无人机飞行小时，包含往返。若区内任务来自不同驻点，底层保留`h_bi`，区域汇总为`h_i`；这属于同一类变量，不是新增技术资源。

人员约束使用：

`地面保护人时 + 无人机配套人时 + 卫星告警处理人时 ≤ 可用于保护工作的总人时`。

无人机配套人时可简化为`γ × 总飞行小时`，γ的单位为人时/机时，合并飞手、观察/协调人员和平均告警图像审核工作量；卫星处理人时计入图像解译与告警审核。地面现场核查已计入x_i，不在技术配套工时里重复计入。若取得实际记录，可将飞行操作与告警处理分开。AI的潜在帮助体现在γ和发现质量的变化，不能假设告警无需人工核查。

无人机上限使用：

`总飞行小时 ≤ 可用无人机数量 × 每架在评价期内可用飞行小时`。

每架可用工时须考虑充电/电池轮换、维护和可飞天气。沿用统一设备可用率时，这些损失在同一口径下合并一次，不分别反复折减。295人仍是题目部门工作人员参考数，须扣除未纳入任务的岗位并按班次换算，不能全部当成全天同时可出动人员。

此外必须限制作业范围与续航：固定候选驻点，按往返飞行、现场监测与安全余量判断是否可达。用驻点作业范围与区域多边形相交获得可覆盖范围；只看到区域中心可达，不代表整个分区均可覆盖。基础版无需优化精细航线，但应扣除往返消耗，将投入的飞行小时换算为现场有效监测小时。

同一地区地面队伍不足或无法及时到达时，增加监测可改善发现，却不能自动取得相同的处置改善。区域月度工时也不能替代值守安排；战略模型使用固定轮班、事件稀疏和响应队伍可出动的明确假设，不模拟频繁并发调度。

## 4. 最少新增数据与已有数据的复用

| 数据/参数组 | 第一版处理 | 进入模型的位置 |
|---|---|---|
| 无人机能力 | 数量、统一可用飞行工时、航速及单次续航/可行作业半径；取明确机型资料或规划情景 | 机时上限、可达范围和往返损耗 |
| 人员配套 | 统一γ、卫星告警处理预留工时、固定角色/班次 | 总人力约束及响应可用性 |
| 分威胁监测效能 | 偷猎与火灾分别设少量全园统一的发现效能，低/中/高情景 | 飞行小时与巡护投入转成发现水平；缺实测时不称校准概率 |
| 卫星服务 | 可用观测机会、观测后发布延迟及无效观测情景 | 火情发现等待和告警核查 |

复用A_i计算投入强度，复用G_i描述开阔或遮挡条件，复用水点位置选择重点核查目标，复用驻点坐标计算空中距离，复用T_bi计算地面响应。生态类型影响可见性时采用明确的粗分级情景，不为每区拟合一套独立参数；同样的监测设备对识别人、动物和火情的能力不能默认相等。

不必为第一版收集每台设备维修记录、训练AI、建立逐动物识别模型或规划逐次航迹。关键能力资料没有来源时使用范围和敏感性情景，不能把示例参数写成公园实测数据。

## 5. 卫星产品的用途边界

- 既定MCD64A1燃烧面积产品用于历史过火暴露、燃烧日期与长期规划，不是实时火警。
- NASA FIRMS的VIIRS产品提供名义375 m活跃火/热异常像元中心，可支持近实时火情提示。NASA说明全球数据通常在卫星观测后3小时内发布；这不是从起火算起的保证，也不是全天连续观测。
- 火警发现等待还包括等到有效过境、云/烟与传感器条件，发布后还要解译、核查和响应。多颗VIIRS卫星的观测时间接近，不能假设它们均匀覆盖全天。
- 热异常点不是精确火边界，不自动证明为有害野火；需要核查。该公开产品不能直接识别单个偷猎者，也不能代替区域物种数量调查。

公开卫星信息服务在各分配方案中保持同一条件，对比时不把共有的监测贡献重复作为某方案独有收益。

## 6. 如何检验配置是否值得

在同一环境、保护价值和可用资源情景下，比较地面巡护方案、人员与无人机协同方案，以及机队或人员减少后的方案。所有方案公平计入飞手、告警核查和响应人力。

主要输出是综合剩余风险指数，以及重点区域有效监测覆盖、发现/到场时间与保护底线达成情况。固定价值尺度和归一化口径，避免因每次重算相对权重而制造“保护改善”。无人机配置结果还要显示来自哪个驻点、投入多少机时、配套占用多少人时以及尚未覆盖的范围。

技术部署后检出事件数可能上升。没有校正观测努力和漏报时，不能以发现的偷猎事件增加判断保护变差，也不能以告警减少单独判断改善。真正损失、及时处置比例与监测质量应区分。

缺乏资源投入与实测后果记录时，以上检验只能支持“假设效能下的相对配置”，不能验证无人机实际降低多少死亡或生态损失。
