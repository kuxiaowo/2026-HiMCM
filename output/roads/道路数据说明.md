# 埃托沙国家公园道路数据：获取、建图与完整性检查

获取日期：2026-10-05。主数据快照：2026-10-03T20:20:50Z。

## 结论

已获得可直接建图的道路矢量数据，包含大量碎石路、土路和 highway=track 的车辙通道。
园内候选机动车路网有 1,447 个节点、1,900 条拓扑路段、3,471.368 km；最大连通分量含道路长度的 99.07%。
可以保留图论方案，但这些数据不能证明公园实际每一条管理道路都已收录，也不能证明每条路当前均允许巡护车辆通行。

## 主要来源与交叉检查

1. Geofabrik / OpenStreetMap：<https://download.geofabrik.de/africa/namibia.html>
   固定快照：<https://download.geofabrik.de/africa/namibia-261003.osm.pbf>，54,709,969 字节。
   原始 PBF 保留 OSM 节点引用、完整道路标签，可建立真实的节点连接关系。
   许可：ODbL 1.0；注明 © OpenStreetMap contributors。原始来源和 SHA-256 保存在 download_manifest.json。
2. HOT / HDX：<https://data.humdata.org/dataset/hotosm_nam_roads>
   提供道路 SHP、GeoPackage 和属性质量报告，包含 highway、surface 等字段。
   同样源于 OSM，不是独立完整性证据。其说明明确表示志愿制数据不能视为穷尽。
3. ArcGIS Etosha_Road_Clip：<https://www.arcgis.com/home/item.html?id=f9f78bd6acef4c44902431c929337817>
   查询得到 985 个道路要素，其中 980 个 OSM way ID 同时出现在当前园内提取中。
   图层字段包含 osm_id，也源于 OSM；没有清楚提供数据方法和许可，只用作交叉检查，未自动合并差异道路。
4. 题目给出的地图网页：<https://www.etoshanationalpark.org/map>
   有 2025 全园、东部、西部地图，适合核查游客主路线，不能替代全量管理道路矢量数据。
5. Atlas of Namibia 2022：<https://atlasofnamibia.online/chapter-10/transport>
   10.32 交通网络的数据说明指向 Africon / Roads Authority 的 2009 AICD 数据。
   数据入口 <http://the-eis.com/elibrary/search/26731> 本次连接失败，未取得矢量文件，未将其当作已验证的数据源。
6. Roads Authority 网站：<https://www.ra.org.na/>
   查到的 Road_Network ArcGIS 服务需要 token；本次未取得此矢量文件。

7. Overture Maps 2026-09-23.1：<https://docs.overturemaps.org/guides/transportation/>
   按公园范围检索获得 1,162 条道路要素，园内总长 3,538.723 km。
   大部分本地数据仍来自 OpenStreetMap；少量来自 TomTom，不是全面独立验证。
   已保留各要素 sources、connectors、来源版本和许可，本次来源许可均为 ODbL-1.0。
   分别保留数据，没有自动拼接成更完整的图。
   修正投影裁切后，Overture 在 OSM 道路 50 m 缓冲之外仅约 0.147 km，形成 1 个大于 100 m 的核查候选。
   来源贡献高度重叠，这种吻合仍不能确认实际巡护道路全集。

## 范围与道路长度

用 OSM relation 2982497 的 Etosha National Park 边界裁切。
边界面积为 22,897.101 km²，与题目参考 22,935 km² 有小幅差异；不是法律边界验证。
长度在 EPSG:32733（UTM 33S）计算，GeoJSON 存储经纬度 EPSG:4326。
投影前将边界加密至不超过 0.001 度，防止稀疏长边投影后误裁北部沿界道路。

园内所有 highway 要素：985 个 OSM way，3,538.357 km。
候选机动车道路：871 个 OSM way，3,471.368 km。
机动车候选图排除 footway/path/construction，以及明确 vehicle/motor_vehicle/motorcar=no 的要素；全部原始道路仍保留在 etosha_roads.geojson 和 road_inventory.csv。

候选道路路面标签分组：

| 类别 | km |
| --- | ---: |
| gravel / fine_gravel | 1,215.506 |
| ground / dirt / sand | 1,110.163 |
| unpaved / compacted 等 | 215.533 |
| 铺装路面 | 30.791 |
| surface 缺失 | 899.375 |

候选道路中 highway=track 为 1,723.822 km。highway 是道路用途/等级，surface 是路面；二者交叉分类，不能将 track 长度与 gravel 长度再次相加。
候选道路总长相当于题目 3,551 km 参考值的 97.76%，这是数量级核对，不是已确认的覆盖率。
不能据此声称只缺失 80 km，或声称收录了实际道路的 97.76%。

## 文件用途

主数据位于 ../../data/roads/processed/：

| 文件 | 用途 |
| --- | --- |
| etosha_roads.geojson | 园内所有已映射道路，包括小径、非机动车道路和施工道路 |
| road_inventory.csv | 原始 OSM way 属性、类型、路面、限制及园内长度 |
| park_nodes.csv | 园内候选机动车图节点 |
| park_edges.csv | 园内候选机动车图连接关系、路段长度和限制 |
| park_edges.geojson | 与边表对应的曲线路段几何 |
| etosha_roads_buffer_5km.geojson | 园界外扩 5 km 的道路，辅助检查入口和园外连接 |
| buffer_5km_nodes.csv / buffer_5km_edges.csv | 外扩范围的候选机动车图 |
| road_control_points.geojson / road_controls.csv | 门、栅栏等通行控制点，供权限与延误检查 |
| park_boundary.geojson | 本次采用的 OSM 公园边界 |

output/roads/etosha_road_map.png 是按路面标签分类的全园道路图。
output/roads/etosha_roads.gpkg 可直接在 QGIS 打开，含公园边界、全部已映射道路、候选机动车拓扑路段、通行控制点，以及 Overture 道路与差异核查候选，共六个图层。
quality_report.json 是机器可读统计和质量报告。
overture_roads.geojson 与 overture_review_candidates.geojson 保留补充源和几何差异核查候选；候选差异不代表已确认漏路。
overture_crosscheck.json 记录比较结果。

## 节点与边表字段

节点：node_id、osm_node_id、lon、lat、x_m、y_m、degree、component_id、boundary_clip。
osm: 前缀表示原始 OSM 节点；clip: 前缀表示边界裁切产生的端点。
barrier、control_name、control_access、control_motor_vehicle 保留通行控制信息。

边：edge_id、u、v、osm_way_id、length_m，以及 highway、surface、tracktype、smoothness、width、maxspeed、oneway、junction、access、vehicle、motor_vehicle、motorcar、bridge、tunnel、layer、seasonal、ford 等。
allow_forward_by_oneway 和 allow_backward_by_oneway 已对应当前边几何方向，只描述单行方向，不表示获准通行。
access_review 表示存在需要核查的道路权限标签；节点上的门与栅栏也需要单独处理。
空字段表示未提供，不代表零、畅通或无风险。

## 拓扑处理与检查

仅按共同 OSM 节点 ID 建立连接，没有把几何上相交的线自动连接。
保留交叉点、原始 way 边界、门与栅栏，以及裁切端点。
只压缩同一 OSM way 内没有分支的度二形状点，保留完整曲线和长度。
没有擅自补道路、吸附断点或推断跨桥连接。
园内图有 20 个连通分量，最大分量长 3,439.130 km。
已检查节点/边编号唯一、端点引用存在、长度为正、压缩前后总长度一致。
图连通性是候选道路的无向拓扑检查，未施加所有单行、通行许可及季节条件。

## 建模注意事项

25.91% 的候选机动车道路长度没有 surface 标签，不能据 highway 等级断定是柏油或土路。
871 个候选 way 中，715 个没有 maxspeed；有 maxspeed 也只是限速标签，不是实际巡护速度。
193 个候选 way 存在 access=no/private/permit/forestry/agricultural/destination 等标签，需要情景化处理，不能直接假定巡护队均可通行。
不连通小分量可能是真实隔离、缺失连接或边界裁切造成，不应直接画直线连上。
可用当前数据做路网距离、候选驻点、巡逻可达性分析；响应时间需要另设有依据的路面/季节速度及权限参数。

## 复现

使用 conda 环境 himcn-roads；环境规格见 ../../environment-roads.yml，实际依赖版本见 ../../scripts/roads/requirements-lock.txt。
运行 scripts/roads/download_sources.py 下载主源，再运行 scripts/roads/build_network.py 生成数据和地图。
scripts/roads/check_overture.py 获取额外交叉核查数据，再运行 scripts/roads/compare_sources.py 生成比较结果及附加图层；这些步骤不是生成主 OSM 图的必要步骤。
