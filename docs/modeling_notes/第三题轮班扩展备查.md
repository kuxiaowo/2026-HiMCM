# 第三题：人力需求与排班可行性模型

> **2026-10-05最新修订：**当前实施以[第二题资源分配方案](第二题资源分配方案.md)和[整体建模计划](整体建模计划.md)第6—7节为准。第二题独立优化可替代地面人时和无人机机时，服务率来自作业时间，不拟合真实减损；固定基本响应，采用精简LP。第三题在同一标准下最小化需求人时，再换算规划人数，不建立复杂轮班MILP。下文发现概率、复杂整数响应及轮班内容保留为早期扩展备查，不是当前必须实施的方案；第一题数据和已算结果仍保留。

更新：2026-10-05。采用用户最新决定：第三题不使用预测模型。本文完成思路与计算计划；尚未估算埃托沙实际所需人数。

## 1. 正确理解第三题

原题第3项同时要求分析保护水平随时间变化、估算维持所选水平所需人员。时间维度可以通过各月、各班次保护需求与人员供给的匹配来回答，不需要预测种群或训练机器学习模型。

核心问题是：**给定保护目标、驻点、技术装备及工作制度，至少需要多少保护岗位人员，才能持续提供所需的巡查、信息核查与及时响应？**

三题职责：第一题确定“达到怎样的保护水平”；第二题确定“已有资源如何分”；第三题确定“维持该水平需要多少人、如何轮班”。第三题与第二题共用资源作用和地理约束，改变优化目标及人员上限的地位。

## 2. 先确定人员估算的条件

人员数必须附带以下条件：

- 全园保护评分与重点对象的最低服务要求。总计划中的80分/重点0.90仅为团队基准示例，不是题目或主管部门标准。
- 固定的候选驻点、可通行道路和响应期限；期限尚需资料或团队假设。
- 指定无人机数量、可用飞行时段、续航及操作要求；卫星解译和告警核查占用人员。
- 工作班次、每周最大工作量、休息、休假和人员技能的口径。
- 不同月份/昼夜的保护需求与资源可用性。无实际时序数据时，使用明确的季节与缺岗情景。

先计算“保护相关人员”，再按非保护岗位或可参与保护比例换算部门总人数。295为部门工作人员参考数，不能直接视为295名巡护人员，也不能视为295人同时在岗。

## 3. 按五步计算，而不是直接将风险换成人数

### 第一步：把保护目标转为服务要求

复用第一题的需求权重与保护指标，规定每个关键时期最低分数、重点对象服务底线和及时到达要求。风险高、价值高只说明需求更大，并不能独立确定“应配几个人”；还必须知道一单位人时能提供多少巡查和响应能力。

### 第二步：求满足目标的必要投入

复用第二题的人时/机时决策与响应可达性。在保护目标约束下配置地面巡查、现场响应、无人机监测和信息核查。技术越多不必然总人数越少：技术可能降低地面发现负担，同时增加飞手、审核和响应需求。

第二题的优化结果适合作为第三题的初始方案。如果第二题在固定人数下追求最高分，该方案可能不是维持较低指定目标的最省人方案。因此第三题需要允许重配置，不能将第二题每区工时锁定后称得到最低人数。

### 第三步：计算每个岗位、每个班次的在岗需求

| 用途 | 所需人力来源 | 必须检查的条件 |
|---|---|---|
| 地面巡查 | 巡护有效人时，加出行等占用 | 每班工作量、可通行范围、有效巡查能力 |
| 现场响应 | 合格队伍的人数和连续值守 | 驻点覆盖、到达时间、专业技能、备用能力 |
| 无人机操作 | 飞手、必要观察/协调人员 | 同时飞行架数、操作人时、日夜资格 |
| 信息处理 | 影像解译、告警核查、调度 | 信息工作量、及时性、共享岗位容量 |

这是人员用途划分，主资源仍是地面人时与无人机机时，不引入任务包。同一人可以在不同班次承担多种职责，同一时段不能被当作两个完整岗位使用。

响应队伍可以在稀疏事件假设下服务多个可达目标，但值守人时仅在驻点计一次。不能将一支队伍分配到多个地区后，把它当成多支同时处置队伍。并发事件另设情景；地面巡查队兼响应时需明确可中断巡查和到达条件，不能同时当作两份满额可用能力。

每班按角色至少检查“总工作量/班次时长”和“同时需要的岗位数”两个下界。即使总工时足够，飞手缺岗、夜间无响应队或技能不匹配都会使方案不可行。

### 第四步：把同时在岗需求转为轮班编制

第一版可采用代表周与可行轮班模板。示例假设：每日三个8小时班次，每人每周最多五班，并设置必要休息；具体休息时长和连班限制待确定。模板先满足这些规则，再决定各类人员分配到哪些模板。

例如一个岗位要求每天24小时都有两人值守，则一周需要`2×3×7=42`个人班次。按每人最多五班计算，工时下界为`ceil(42/5)=9`人。**9人仅是工时下界**；技能、休息、休假和不可用情景还需排班检验。该例解释计算口径，不是埃托沙的人员结果。

常规休息放在轮班模板中；年假、培训、病假等若通过可用率或明确缺岗处理，只折减一次。响应备用队若已占值守人时，也不再用同一项备用系数重复放大。

### 第五步：优化最少人数并检验持续达标

主要决策是各技能组的总人数、各班次/模板的人数、地面人时、机时和响应值守。目标为保护岗位人数最小，同时满足所有时期的保护目标、技术和人时上限、岗位并发及轮班规则。

“全园年度平均80分”不能代替“每个关键班次达到80分”。结果至少给月度评分、最弱班次、重点对象短板和各岗位缺口。不同月份可重分配同一编制；不能把所有月份所需人数相加作为总编制。

## 4. 算法选择

主算法为混合整数线性规划（MILP）。人员、队伍和轮班人数为整数；人时与机时为连续变量。复用第二题的分段线性发现能力和目标点响应可达变量。

定义`n_r,ℓ`为技能组`r`安排到可行轮班模板`ℓ`的人数，`a_ℓ,t`为模板在班次`t`是否在岗。该班次的人员供给为`Σ_ℓ a_ℓ,t n_r,ℓ`，需满足工作量和同时岗位要求；各用途共用的人员池应按容量约束分配，不能重复计算。

可用现有conda环境中的SciPy MILP接口，实施前检查版本。若采用按候选人数二分，内层必须判断在所有约束下是否可行。局部非线性优化找不到方案，不足以证明该人数不可行。

报告“最低人数”需要可行解和最优性依据。求解超时或存在近似时，应报告可行人数上界、求解下界/gap及适用假设。

## 5. 时间变化怎样体现

| 时间变化 | 在模型中改变什么 | 要报告什么 |
|---|---|---|
| 昼夜 | 监测能力、飞行许可/能力、同时在岗安排 | 各班保护能力与缺岗 |
| 火管理季节 | 火侧需求、合格响应安排 | 季节岗位需求、编制峰值 |
| 旱季水源压力 | 已明确的水源巡检与重点监测要求 | 检查工时与岗位占用 |
| 休假、培训、病假 | 可用人员/技能和模板供给 | 备用与替班需求 |
| 无人机停用、道路封闭 | 发现能力、巡查人时、响应可达性 | 达标可行性及短板 |

这些是给定条件下的保障分析。事件次数、动物数量和生态恢复不作为第三题的预测输出。无人机减少、人员减少和巡护安排调整等系统比较，进一步放在第四题敏感性分析。

## 6. 最少需要补齐的数据

不要求取得所有人的真实排班或所有事件记录，但必须至少明确：保护目标、驻点/响应时限、单班制度、保护岗位可用人数口径、响应队最低规模与技能、无人机操作人力、信息处理工时、统一巡查/监测效能范围。

第一版可将制度和效能设为共享假设与区间，避免逐区增加参数。当前道路响应、实际火暴露及部分重点目标未完成，人员数仍无法可信求解。

## 7. 输出与验证

输出：保护岗位总编制、技能/用途构成、各驻点各班次在岗人数、可行轮班、每期评分/重点底线、与现有可用人数的缺口，以及机队和工作制度条件。

验证：人时与同时岗位不重复、每班响应/操作资格满足、休息与轮班成立、每期保护要求达标、不可达区域没有被加人虚假覆盖。人数变化还应检查是否由目标、参数或设备条件导致。

若固定驻点或技术造成目标不可达，先报告不可行原因，调整部署条件或目标再计算，不能给出一个表面上很精确的人数。
